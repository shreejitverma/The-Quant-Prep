# Note Conventions

How every note in this repo is written, so that Obsidian, GitHub, the `qp` CLI and the web dashboard all read it the same way.
`./qp check` enforces the machine-checkable parts of this page; CI runs it on every change.

## Files and ids

- A topic note lives in a numbered section folder and has a two-digit order prefix: `01-Probability/04-Expectation-Variance-and-Linearity.md`.
- The note id is the file name without the prefix, lower-cased: `expectation-variance-and-linearity`.
  Ids are what `prereqs`, firm `focus` lists and `qp` commands use, so renumbering a file never breaks them.
- Every section has a `README.md`.
  The table between the `qp:moc` markers is generated by `./qp index`; write only outside the markers.
- Runnable code sits next to the notes that use it, in the section's `code/` folder.

## Frontmatter

```yaml
---
type: concept          # concept | problem-set | playbook | guide | reference | firm | moc
track: [quant-trader, quant-research, quant-dev]   # who needs it
tier: core             # core | advanced | senior
status: seed           # seed | draft | solid | canonical
prereqs: [conditional-probability-and-bayes]       # topic ids
est_hours: 4           # focused study time to reach "solid" mastery
sources: []            # URLs or citations used while writing
---
```

- `concept`, `problem-set` and `playbook` notes are topics: learners mark their mastery and they appear in plans.
- `guide`, `reference`, `firm` and `moc` notes are supporting material.
- Frontmatter is flat: scalars and inline `[a, b]` lists only.
- Tiers mean: `core` is expected of every candidate for the track, `advanced` separates strong candidates, and `senior` is expected of experienced hires.

## Status

| Status | Meaning |
| :--- | :--- |
| `seed` | Objectives and references only. The backlog of unwritten notes. |
| `draft` | Partly written; may lack sections or cards. |
| `solid` | Complete: every required section, at least 6 cards (15 for a problem set), and all maths checked. |
| `canonical` | `solid`, and reviewed by a human against the references. Only a human sets this. |

## Required sections for `solid`

Use these `##` headings in this order, then any extra sections you need:

1. `## TL;DR` - three to six bullet points a candidate should be able to say from memory.
2. `## Learning objectives` - carried over from the seed.
3. `## Core concepts` - the theory, with derivations where interviews ask for them.
4. `## Worked examples` - fully solved problems, with the reasoning written out as you would say it in an interview.
5. `## Pitfalls` - the common mistakes and misconceptions.
6. `## Interview questions` - question cards (below).
7. `## Further reading` - books, papers and links.

A `## In this repo and SDE-Interview-Prep` section, when present, lists code in this repo and bridge links into SDE-Interview-Prep.

## Question cards

Cards feed spaced review (`qp review`, the web dashboard).
Each card is a collapsible Obsidian callout whose title line carries a stable id and the prompt, followed by the answer:

```markdown
> [!question]- prob-two-dice-sum-seven | Two fair dice are rolled. What is the probability that the sum is 7?
> $1/6$. Six of the 36 equally likely ordered outcomes sum to 7: (1,6), (2,5), ..., (6,1).
```

- The id is kebab-case, unique across the whole repo, and starts with the section prefix: `prob`, `stat`, `la`, `sc`, `deriv`, `fi`, `ms`, `mm`, `alpha`, `ml`, `risk`, `qd`, `int`.
- Never change an id once published: review history is keyed on it.
- The prompt stays on the title line; the answer is every following line that starts with `>`.
- Leave a blank line between cards, or Markdown merges them into one quote.
- Answers give the result first, then the shortest convincing argument.
- Answers must be correct; check every number.

## Maths and style

- Inline maths `$...$`, display maths `$$...$$` on their own lines; GitHub, Obsidian and the dashboard all render them.
- One sentence per line in prose.
- No emojis and no em dashes; use a plain `-`.
- Link notes with relative Markdown links (`[Greeks](../05-Derivatives-and-Volatility/05-The-Greeks.md)`), not wikilinks, so the links work on GitHub too.
- Link SDE-Interview-Prep with absolute GitHub URLs (`https://github.com/shreejitverma/SDE-Interview-Prep/blob/main/...`); `./qp check` verifies each target exists in your local clone (`SDE_REPO`, default `../SDE-Interview-Prep`).
- Firm guides state facts about a firm only with a source, and flag anything that may have changed.
